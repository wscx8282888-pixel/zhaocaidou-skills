# 销售口语 → 结构化字段 (LLM 抽取规范)

销售跟你 (Claude) 说的是口语, hub 表要的是枚举值。这份文档定义抽取规则 + 8 个真实场景示例。

## 总原则

1. **能抽就抽, 抽不准宁可留空**。空字段 hub 不动飞书侧值; 错字段会污染表 (虽然不在白名单的值会被 skip)。
2. **跨字段一致性**: `followupStatus="无意向"` 应该配 `feedbackQuality="不合适"`; `followupStatus="已成单"` 应该有 `dealAmount`。
3. **日期算到具体日**: "下周一" "明天" "周五" 这种 LLM 自己算出 ISO `YYYY-MM-DD` 再传。今天日期从系统 (例如 `date -I` 或 Claude 自己知道的当前日期)。算不准就留空, 让销售自己说。
4. **金额必须数字**: "5万" → `50000`, "首单 12 万 5" → `125000`, "120k" → `120000`。带"差不多"、"大概"、"几万" → 留空, 让销售确定。
5. **草稿必须给销售看**。LLM 抽完按下面格式列出来, 销售确认后才 POST。

## 字段白名单速查 (跟 hub 对齐, 不在白名单 hub 会 skip)

| 字段 | 白名单 |
|---|---|
| `followupStatus` | `未联系` / `已联系` / `已跟进` / `已加微信` / `已绑店` / `已成单` / `无意向` |
| `feedbackQuality` | `质量好` / `一般` / `不合适` |
| `communicationResult` | `线上推进中` / `计划线下拜访` / `放弃跟进` |

free text: `unsuitableReason` / `additionalRequest`  
number: `dealAmount`  
ISO date: `nextFollowupDate`

## 状态语义 (避免抽错)

- **已联系**: 拨通电话 / 发了微信好友请求 / 发了消息, 但客户**还没正经回应**
- **已跟进**: 有过实质沟通, 客户表了态 (积极或观望)
- **已加微信**: 客户接受好友且能继续聊
- **已绑店**: 客户开始接入业务系统了 (具体看产品定义, 销售自己分辨)
- **已成单**: 签合同/付款了
- **无意向**: 客户明确拒绝或是行业不匹配

**`已跟进` 和 `已加微信` 可以叠加**, 但飞书表字段只能选一个。如果用户同时提到, 优先 `已加微信` (因为它是更具体的状态)。

## 8 个示例 (覆盖常见场景)

### 例 1: 简单加微信

**销售说**: "杭州那家越禾我加上微信了"

**抽**:
```json
{
  "followupStatus": "已加微信",
  "communicationResult": "线上推进中"
}
```

**草稿确认**:
> 我准备这样写:
> - 公司: 杭州越禾 (recXXX)
> - 跟进状态: 已加微信
> - 沟通结果: 线上推进中
>
> 对吗?

### 例 2: 打了没人接

**销售说**: "上海艾博那家打了, 没人接, 留了语音"

**抽**:
```json
{
  "followupStatus": "已联系"
}
```

(`feedbackQuality` 留空 — 没接通没法判断质量; `communicationResult` 也留空 — 不算推进)

### 例 3: 客户不合适

**销售说**: "深圳那家不合适, 他做的不是亚马逊是 Temu, 不是我们目标用户"

**抽**:
```json
{
  "followupStatus": "无意向",
  "feedbackQuality": "不合适",
  "unsuitableReason": "不是亚马逊卖家, 做 Temu"
}
```

### 例 4: 约了线下见面

**销售说**: "广州天裕那家聊得不错, 下周二我去他公司聊"

**今天是 2026-05-25 (周一), 下周二 = 2026-06-02。**

**抽**:
```json
{
  "followupStatus": "已跟进",
  "feedbackQuality": "质量好",
  "communicationResult": "计划线下拜访",
  "nextFollowupDate": "2026-06-02"
}
```

### 例 5: 客户要更多资料

**销售说**: "兴时达那家有意向, 让我发份服务费率表过去"

**抽**:
```json
{
  "followupStatus": "已跟进",
  "communicationResult": "线上推进中",
  "additionalRequest": "客户索要服务费率表"
}
```

(`feedbackQuality` 留空 — "有意向" 不到 "质量好" 的程度, 但显然不是"一般"或"不合适", 留空让销售决定)

### 例 6: 成单

**销售说**: "鸿景那家签了, 首单 12 万 8"

**抽**:
```json
{
  "followupStatus": "已成单",
  "dealAmount": 128000
}
```

**草稿强调金额单位**:
> - 公司: 鸿景 (recXXX)
> - 跟进状态: 已成单
> - **成单金额: ¥128,000 (12.8 万)**
>
> 金额对吗?

### 例 7: 持续跟进, 下次约时间

**销售说**: "之前加了微信的张总, 今天又聊了, 他说月底再决定要不要试, 周五我再 ping 他"

**今天 2026-05-25 周一, 周五 = 2026-05-29。**

**抽**:
```json
{
  "followupStatus": "已加微信",
  "communicationResult": "线上推进中",
  "nextFollowupDate": "2026-05-29",
  "additionalRequest": "客户月底决定是否试用, 周五跟进确认"
}
```

(注意: 即使之前已经标过"已加微信", 这次还是写"已加微信" — 因为这是当前最准确的状态。hub PATCH 语义, 同值无副作用)

### 例 8: 模糊语气 (要追问)

**销售说**: "翠岚那家差不多算成了吧"

**这种**不要直接抽**, 反问:
> "差不多算成是什么意思呢? 是已经签合同了 (已成单), 还是口头同意 (已跟进)? 有金额吗?"

抽到能 commit 的具体描述再写草稿。

## 边界情况

### 销售提到多家公司

"我今天联系了 5 家, 都标已联系吧"

→ 列出"你说的 5 家是: A, B, C, D, E, 对吗?" 让销售确认每家都在他名下。**批量操作要更谨慎**, 逐条 POST 不要并行 (一条失败容易遗漏)。

### 销售给了 recordId 不在他名下

"recABCD 这条标已联系"

→ 先 GET /ai-leads 过滤 assignedTo == 我, 检查 recABCD 在不在结果里。不在 → 拒绝: "recABCD 不是分配给你的, 我不能改"。

### 销售口语跟字段冲突

"已经成单了, 但还在跟进中"

→ 不要硬抽。问销售: "成单了应该是终态了, 还在跟进是什么意思? 是已成单但还有交付要跟? 还是其实没完全成?"

### 日期不确定

"下周吧, 具体哪天看他时间"

→ `nextFollowupDate` 留空。回话: "下周具体哪天确定后再告诉我, 我帮你写上"。
